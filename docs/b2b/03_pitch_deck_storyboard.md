# SY Valuation API — B2B 제안서 스토리보드 (10장)

작성일 2026-11-25 · 대상: 증권사(리테일 AI 어시스턴트·IB), 대기업 전략기획실(M&A·투자검토)
발표 20분 + 라이브 데모 5분 기준. 각 장은 **헤드라인 → 본문 → 시각 요소 → 발표 멘트** 순.

> **문구 원칙 (전 장 공통)**
> - "오차율 0% 보장" 은 쓰지 않는다. 결정론이 보장하는 것은 *재현성*과 *산식 구현의 정확성*이다. 입력 데이터·가정의 옳음까지 보장한다고 읽히면 계약·법무 리스크가 된다. → **"계산 재현율 100%"**, **"LLM 산술 오류 0건(계산에 LLM 미개입)"** 으로 표기.
> - `[검증 필요]` 표시가 붙은 수치는 자체 벤치마크·PoC 로 채운 뒤 사용한다. 지금 넣으면 근거 없는 숫자다.
> - 모델 수 표기는 실제 구현에 맞춘다: 3대 접근법 · 11개 산식(SY 평가법) + 고전 모델(RIM·Graham·Lynch). 요청서의 "9개 모델" 은 다중모델 엔진 기준이므로, 대외 표기를 하나로 확정한 뒤 전 장에 통일.

---

## 1장 — 표지

**헤드라인:** AI 가 말하고, 숫자는 엔진이 계산합니다
**부제:** SY Valuation API & MCP — 사내 AI 에이전트를 위한 결정론적 기업가치평가 엔진
**하단:** 회사명 · 발표자 · 일자 · "본 자료의 모든 화면은 실제 API 응답입니다"
**시각:** 좌측 대화형 에이전트 말풍선("삼성전자 적정가치는?") → 가운데 `tools/call` 화살표 → 우측 계산 엔진 박스. 엔진 박스에만 강조색.
**멘트:** "오늘 보여드릴 것은 앱이 아니라, 귀사 AI 가 호출할 계산기입니다."

## 2장 — Problem ①: LLM 은 계산기가 아닙니다

**헤드라인:** 기업 분석 에이전트의 숫자, 누가 책임집니까
**본문:**
- 범용 LLM 은 DCF·WACC 같은 다단계 산식을 **확률적으로 생성**한다. 같은 질문에 다른 적정가가 나온다.
- 흔한 실패: 할인 기간 지수 오류, 영구가치 산식 혼동, 단위(억/조·주당/총액) 혼선, 순차입금 부호 반대.
- 답변은 유창해서 **틀린 숫자가 틀려 보이지 않는다.** 리테일 고객 응대·투자심의 자료에 그대로 들어간다.
- 감사·민원 시점에 **그 숫자를 다시 만들어낼 수 없다.**
**시각:** 동일 프롬프트를 3회 실행한 결과 3개를 나란히(적정가가 서로 다름) `[검증 필요: 자체 벤치마크 50문항 결과로 교체]`
**멘트:** "문제는 LLM 이 틀린다는 게 아니라, 언제 틀렸는지 알 수 없다는 것입니다."

## 3장 — Problem ②: 공시 데이터 정합성이 깨집니다

**헤드라인:** 숫자의 절반은 산식, 나머지 절반은 어떤 공시를 읽었느냐
**본문:**
- DART 원문은 그대로 쓸 수 없다: 연결/별도, 누적/분기(3분기 보고서는 누적값), 정정공시, 계정과목명 불일치, 지배/비지배 구분.
- RAG 로 공시를 붙이면 LLM 은 **작년 사업보고서와 올해 반기보고서를 섞어** 답한다.
- TTM(최근 4분기 합산)을 직접 만들지 않으면 평가 기준 시점이 종목마다 달라진다.
- 결과: 같은 회사를 두 부서 에이전트가 다르게 평가한다.
**시각:** 공시 타임라인(사업보고서 → 1Q → 반기 → 3Q → 정정) 위에 "LLM 이 읽은 지점" 과 "TTM 이 써야 할 구간" 을 대비.
**멘트:** "저희는 이 정제 과정을 엔진 안에 넣었고, 응답마다 어떤 공시 기준인지 명시합니다."

## 4장 — Solution: 결정론적 계산 엔진

**헤드라인:** 같은 입력이면 언제나 같은 결과 — 계산에 LLM 은 없습니다
**본문 (3단):**
- **3대 접근법 · 11개 산식** — 수익가치(FCFF DCF·EBITDA 멀티플·영업이익 배수) / 자산가치(순자산·청산·조정 NAV·NNWC) / 상대가치(PER·PBR·PSR·EV/EBITDA)
- **결정론적(Deterministic)** — 순수 함수 구현. 모든 응답에 `input_hash` 와 엔진 버전. 1년 뒤 감사에서도 같은 값을 재현.
- **근거 포함** — 적용된 가정(WACC·성장률·피어), 재무 기준(예: "DART 2026 3분기 TTM"), 모델별 중간값을 함께 반환.
**증빙 박스:** 계산 재현율 100% · 산식 검증 리포트(골든 테스트 N개사, 수기 엑셀 대조) `[검증 필요: 검증 팩 완료 후 수치 기입]`
**시각:** 응답 JSON 일부(`deterministic: true`, `input_hash`, `provenance`)를 실제 캡처로.
**멘트:** "LLM 은 질문을 이해하고 설명을 쓰는 데만 씁니다. 숫자는 한 줄도 만들지 않습니다."

## 5장 — Product: Headless API + MCP 플러그인

**헤드라인:** 화면 없이, 귀사 시스템 안에서 동작합니다
**본문 (2열):**

| REST API (시스템 연동) | MCP 서버 (AI 에이전트 연동) |
|---|---|
| `POST /v1/valuations/compute` — 가정·재무를 받아 계산 | `get_valuation` — 상장사 평가 |
| ticker 만 주면 공시 기반 자동 평가 | `compute_valuation` — 시나리오·비상장 |
| 재무 직접 입력 → 비상장·딜 타깃 평가 | `search_company` · `screen_undervalued` |
| 2축 민감도 표 동시 반환 | 도구 설명에 단위·기준일·인용 규칙 내장 |
| OpenAPI 3.1 스펙 제공 | Claude·사내 에이전트 프레임워크 호환 |

**시각:** 앱 시뮬레이터 화면 캡처 + 우측 API 콘솔(curl / MCP tool call 탭).
**멘트:** "지금부터 보실 앱 화면은 전부 이 API 응답입니다. 콘솔을 열어 확인하겠습니다." → **라이브 데모 5분**

## 6장 — Integration: 하루 만에 붙습니다

**헤드라인:** 설정 4줄, 연동 1일
**아키텍처 다이어그램(텍스트):**

```
┌──────────────────────── 고객사 내부망 ────────────────────────┐
│                                                              │
│  [리테일 AI 어시스턴트]   [IB 딜 검토 포털]   [전략기획 대시보드]  │
│          │ MCP                 │ REST               │ REST    │
│          ▼                     ▼                    ▼         │
│   ┌────────────── API Gateway (사내 인증·로깅) ─────────────┐  │
│   └──────────────────────────┬─────────────────────────────┘  │
└──────────────────────────────┼────────────────────────────────┘
                               │ HTTPS · API Key / OAuth 2.1
                               ▼
        ┌──────────────── SY Valuation ────────────────┐
        │  MCP Server (/mcp)      REST API (/v1/…)     │
        │            └──────┬──────────┘               │
        │        결정론적 계산 엔진 (3접근법·11산식)       │
        │            ▲                 ▲               │
```

**연동 일정:** 오전 API 키 발급·샌드박스 호출 → 오후 에이전트에 MCP 서버 등록(설정 스니펫 4줄) → 익일 사내 프롬프트 튜닝. *기존 에이전트·게이트웨이가 있는 경우 기준이며, 망분리 환경의 방화벽·보안 심사 기간은 별도.*
**시각:** 위 다이어그램 + MCP 설정 JSON 4줄.
**멘트:** "새 시스템을 들이는 게 아니라, 이미 있는 에이전트에 도구 하나를 추가하는 일입니다."

## 7장 — Use Case: 부서별로 이렇게 씁니다

**헤드라인:** 한 엔진, 세 가지 업무
- **리테일 AI 어시스턴트** — "이 종목 지금 비싼가요?" 에 재현 가능한 3접근법 범위로 응답. 근거·기준일 자동 표기, 등급·추천 문구는 고객사 정책에 따라 비활성.
- **IB · 리서치** — 하우스 WACC·피어 그룹을 넣어 수십 종목 일괄 재평가, 민감도 표를 보고서에 바로 삽입.
- **전략기획 · M&A** — 비상장 타깃 재무를 직접 입력해 1차 밸류에이션 범위 산출. 입력은 저장하지 않는 순수 계산 호출.
**시각:** 3열 카드, 각 카드에 실제 요청 1줄·응답 핵심 3줄.
**멘트:** "세 부서가 같은 엔진을 쓰면, 같은 회사를 다르게 평가하는 일이 없어집니다."

## 8장 — Trust: 금융사가 묻는 것들

**헤드라인:** 검증 가능하고, 통제 가능합니다
- **검증** — 방법론 백서, 골든 테스트·수기 대조 검증 리포트 제공. 엔진 버전 고정(버전 변경 시 사전 고지·병행 운영).
- **감사** — 모든 호출에 `request_id`·`input_hash`. 동일 해시 재호출로 사후 재현.
- **데이터** — 공시는 DART 공공데이터, 시세·컨센서스는 고객 보유 라이선스 연동(BYO-data). 조용한 대체 없음: 데이터 품질 등급을 응답에 표기.
- **보안** — 전용 인스턴스 시 고객 VPC/온프레미스 배치, 입력 재무 미저장 옵션, 국내 리전.
- **규제** — 계산 도구로 제공. 투자 권유·자문 문구는 포함하지 않으며 최종 판단은 고객사.
`[현재 상태 주의: 전용 인스턴스·국내 리전·ISMS-P 는 로드맵 항목. 확정 전에는 "제공 예정(시기)" 으로 표기]`
**시각:** 체크리스트 5행 + "제공 중 / 제공 예정" 구분 열.

## 9장 — Pricing: 호출 과금 + 전용 인스턴스 하이브리드

**헤드라인:** 작게 시작하고, 필요할 때 전용으로
`[아래 금액은 가설. PoC 2곳의 예산 구조 확인 후 확정]`

| 플랜 | 대상 | 과금 | 포함 | 가격(가설) |
|---|---|---|---|---|
| **Sandbox** | 평가·PoC | 무료 | 월 1,000콜, 상장사 조회, 공유 인프라 | 0원 |
| **Growth** (Call-based) | 단일 팀·서비스 | 기본료 + 종량 | 월 5만 콜 포함, REST+MCP, 표준 SLA 99.5% | 월 300만원 + 초과 콜당 40~80원 |
| **Business** (Call-based) | 다부서·대고객 서비스 | 구간별 약정 | 월 50만 콜, 배치 API, 가정 프로파일, SLA 99.9%, 전담 채널 | 월 1,500만원~ |
| **Enterprise Dedicated** | 금융사 내부망·망분리 | 구축비 + 연 라이선스 | 고객 VPC/온프레미스 전용 인스턴스, 무제한 내부 호출, 하우스 방법론 주입, 보안 심사 지원 | 구축 1~2억원 + 연 1.5~3억원 |

**호출 단가 차등(가설):** 조회형(`get_valuation`) 1 크레딧 · 계산형(`compute`, 민감도 포함) 3 크레딧 · 배치 종목당 0.5 크레딧.
**부가 옵션:** 커스텀 방법론 개발, 리포트 생성(PDF/엑셀), 온사이트 교육.
**멘트:** "PoC 는 4주 무상입니다. 성공 기준을 먼저 합의하고 시작하겠습니다."

## 10장 — Next Step: 4주 PoC 제안

**헤드라인:** 4주 안에 귀사 에이전트에서 검증합니다
- **1주차** 샌드박스 키 발급, 대상 업무 1개·종목군 선정, 성공 기준 합의(예: 수치 오류 건수, 응답 시간, 재현율)
- **2주차** 사내 에이전트/포털 연동, 하우스 가정 반영
- **3주차** 실사용자 10~20명 파일럿, "LLM 단독 vs 엔진 연결" 비교 측정
- **4주차** 결과 리포트, 도입 형태(SaaS/전용)·견적 제시
**요청 사항:** 실무 담당자 1명(AI/IT) + 현업 검증자 1명(리서치/딜), 보안 심사 창구
**연락처 · QR(샌드박스 문서)**
**멘트:** "오늘 보신 데모를, 다음 달에는 귀사 화면에서 보시게 하겠습니다."

## 부록 — 예상 질문과 답

| 질문 | 답 |
|---|---|
| "오차가 정말 0입니까?" | 계산은 결정론적이라 재현율 100%이고 산식은 검증 리포트로 증빙합니다. 다만 결과는 입력 데이터와 가정에 따라 달라지며, 그래서 가정을 전부 응답에 노출하고 고객이 바꿀 수 있게 했습니다. |
| "FnGuide·블룸버그와 뭐가 다릅니까?" | 그쪽은 데이터와 단말기입니다. 저희는 에이전트가 호출하는 계산 계약입니다. 귀사가 이미 구독 중인 데이터를 입력으로 연결할 수 있습니다. |
| "우리 방법론과 다르면?" | 가정(WACC·피어·가중치)을 프로파일로 주입합니다. 산식 자체의 커스텀은 Enterprise 범위입니다. |
| "LLM 이 도구 결과를 왜곡하면?" | 도구 설명·서버 지침에 인용 규칙을 넣었고, 구조화 응답(`structuredContent`)을 화면에 직접 렌더링하면 LLM 문장을 거치지 않습니다. |
| "투자자문 규제는?" | 계산 도구로 제공하며 추천·등급은 기본 비활성입니다. 법률 검토 의견서를 제공합니다. `[검토 완료 후]` |
